# Plan: v1.1.0, DOB mismatch as a clustering cannot-link

## Problem (found by project 02, cdp-reference)
Two records with identical first names and different birth dates are correctly
scored REVIEW (`exact_id_dob_mismatch`): a same-name parent and child (Jr./Sr.).
But a third record with no DOB (in 02, a web form fill) can exact-match both on
the shared email or phone. Clustering joins all three through it, because the
cannot-link check only covers conflicting identifiers (email AND phone differ).

## Change
- `merge.cluster_matches`: inside a component, a pair with identical first names
  (the same test the scoring rule uses) and both DOBs present and different is a
  cannot-link, handled exactly like a conflicting-identifier pair: edges are added
  strongest first and skipped if they would join the pair.
- A reviewer approval of that exact pair (a `human_approved` link via
  `--decisions`) lifts the DOB cannot-link for that pair only, because DOB typos
  happen. The identifier-conflict safety rule stays non-overridable.
- `SplitInfo` gains `dob_mismatches` (pairs kept apart by birth date). Review
  queue text and decision handling learn about DOB-only splits.
- No threshold, weight or config value changes.

## Proof
1. A test reproducing the bridge case fails on v1.0.0 code, passes after.
2. CI sequence: uv sync --locked, ruff format --check, ruff check,
